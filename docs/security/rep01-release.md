# REP-01: complete cash reports

Reports now filter in SQL by the authenticated tenant and Asia/Tashkent business dates. Totals and counts cover every matching row; payment/debt lists load 50 rows each with deterministic created_at/id ordering. URL parameters preserve period and pagination on reload and back/forward navigation. Changing the period resets pagination. SSR fetches use one RepeatableRead snapshot for consistent totals and rows. No schema migration is needed.

CSV export uses the same tenant/date SQL and a keyset cursor over both ledgers. It reads 500 rows per batch, awaits stream backpressure, and uses a single RepeatableRead snapshot so concurrent edits do not duplicate or omit rows. The snapshot has a 60-second timeout; a timeout or cancellation aborts the download rather than marking a partial file successful. Very large/slow exports may need a background export job later. Text cells escape CSV and spreadsheet formulas. Numeric amounts retain decimal precision, including negative values. This export is a period report, not the tenant JSON backup/restore format.

Validation: PGlite executes production SQL against 2501 payments plus 101 debts, with exact totals, historical dates, both Tashkent day boundaries, equal timestamp pagination, another tenant, an inconsistent cross-tenant join, and complete multi-batch export. Jest covers URL validation, pagination/count UI, CSV escaping, auth, tenant scope, stream errors and cancellation. TypeScript, changed-file ESLint and production build are release gates. PGlite is not a native multi-connection Postgres load test; large-dataset EXPLAIN/load measurement remains PERF-01/CAP-01.
